### LEARN entries
[LEARN:gotcha] Finding: Parallel image Read calls can return results in an
order that does not match the invocation order — four photos came back
shuffled, and captions were written under the wrong pictures. File size
fingerprints contradicted the reads, and a labeled contact sheet (one HTML
grid screenshot naming each file) settled it in a single unambiguous read.
Impact: Content identification from multi-image reads is unreliable.
Apply: When mapping several images to names, build one labeled contact sheet
and read it once; never trust parallel read ordering for content identity.

[LEARN:technical] Finding: `sips` HEIC→JPEG conversion keeps the pixels in
sensor orientation and records an EXIF orientation tag (6). Browsers honor
the tag, but Hugo's image resizer ignores it, so theme-processed variants
(featured banner, WebP srcsets) come out rotated 90°.
Impact: Photos look fine in Finder/Chrome but sideways on the Hugo site.
Apply: Bake orientation into pixels before committing site images —
`PIL.ImageOps.exif_transpose()` then re-save (also recompresses smaller:
1.8 MB → 1.23 MB for these four).
